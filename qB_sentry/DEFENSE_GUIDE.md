# B 题代码导读与答辩提纲

## 代码入口与职责

| 模块 | 输入→输出 | 建议讲解重点 |
|---|---|---|
| planner.py | 栅格→可行图→路径 | GridMap 的坐标/净空，search 的松弛、堆、父节点与可选代价 |
| run_planning.py | 原地图和查询→基本题路径/比较表 | 端点检查、CSV、官方检查及启发式对比 |
| build_map.py | PCD→降噪、候选面、调平点云 | 最大平面不是地面，法向旋转与高度平移 |
| terrain_advanced.py | 调平点云→早期地形/异常裁剪 | 历史方法和外壳证据；不是最终自建图入口 |
| register_map.py | 早期图→两朝向初配准 | SE(2) 和双向最近邻，供精配准初始化 |
| reconstruct_map.py | 调平点云→最终独立栅格 | 可靠支持面、中位数、受限三角和分层插值、小台阶 |
| refine_registration.py | 独立图+参考图→配准图 | 训练/留出、近对称歧义，未读取查询 |
| compare_maps.py / evaluate_optimized.py | 配准图+查询→路径/跨图检查 | 自建通过和跨图失败是两种不同结论 |
| audit_reconstruction.py | 支撑面/变换→删点与敏感性审计 | 留出恢复不等于未知区真值；扰动下重新规划 |
| robust_boundaries.py | 两图+固定变换→融合地图/风险路径 | 27 种扰动、硬碰撞与软风险、固定路线敏感性 |
| decision_sim.py | 地图+场景事件→六状态日志/视频 | 五类输入、优先级、迟滞、失败停留 |
| visualize_advanced.py | 结果→状态图/地形示意/搜索视频 | 视频不是实际执行性能基准 |
| verify_submission.py | 已保存地图/路径→55次复核证据 | 文件哈希、原端点、点距、整段检查和官方末行解析 |
| test_*.py | 合成及确定性场景→24项测试 | 测试保护什么、没证明什么 |

## 建议 6～8 分钟讲解顺序

1. **约 1 分钟：任务与结果。** 展示三类结果表。基本题前五组可达，六七组按原因拒绝；自建图独立生成；最新融合路线同时通过三图。
2. **约 1 分钟：从 Dijkstra 到 A*。** 打开 planner.py：堆的优先级由 g 改成 g+h，松弛与父节点回溯不变。说清八邻域 octile 下界，以及机器人半径如何转成可行格。
3. **约 2 分钟：建图比搜索更难的地方。** 展示调平点云、表面重建图。解释墙面误识别风险、全局高度阈值失败、插值与未知区、灰度205纠错。
4. **约 1 分钟：配准与两张地图。** 说明刚体变换、训练/留出、朝向歧义和约0.199m轮廓残差。自建路径跨图失败不能归咎于检查器。
5. **约 1～2 分钟：最新优化和第3组。** 展示 paths_and_risk.png；融合只增加禁止区，风险代价鼓励绕行；第3组18/27是固定起点上限，不声称全部成功。
6. **约 1 分钟：决策与边界。** 播放 simulation.mp4，说明注入事件、六状态与迟滞，最后说明没有实车与动态障碍验证。

## 常见追问及回答要点

**你有 ACM 背景，这题和普通网格最短路有什么区别？**
搜索主体类似，难点在构图：原始点云不是图，坐标轴、未知区域、机器人尺寸、坡道/台阶和配准决定了边是否存在。错误建图时，再正确的 Dijkstra 也只是在错误模型上求最优。

**为什么不用现成 A* 库？Open3D 和 SciPy 算违规吗？**
题目禁止现成规划库，搜索确实用 heapq 手写。Open3D 用于点云预处理；SciPy 用于邻域、三角插值和配准，不提供本项目的路径规划。

**半径膨胀怎么做，是否降低了标准？**
用到占据/未知格中心的距离，按原半径0.30m筛选，并阻止斜向穿角。当前实现还保留很小数值容差，严格边界可能更保守；没有缩小半径。这个栅格约定是题目检查器的模型，不是连续实体边界的完整几何证明。

**第3组为什么不能让27种都过？**
先检查路径第一个点，9种情形已不满足净空。任何保持该起点的路径都包含这个无效状态，所以改后续路线不能解决。18/27不是全范围概率，也不是成功率估计；只是27个指定离散扰动的计数。

**99.956%是否可以说基本安全？**
不能据此忽略起点。它是约1cm间距内部采样中对所有情形均安全的比例，不是安全概率或连续弧长证明；整条路径仍只有18/27种通过。危险发生在起点尤其不能用高总体比例掩盖。

**±5cm是不是你的定位误差？0.199m又是什么？**
前者是人为选定的敏感性测试幅度，后者是结构点到最近参考轮廓距离中位数，不是有真值标定的位姿误差。不能把两者当成同一种误差，也没有据此推导高斯置信区间。27种小扰动不覆盖180°朝向歧义。

**融合是不是拿标准答案当自建地图？**
独立建图文件保留且不读参考图。配准使用参考图估计坐标变换；最新另存的融合图显式使用参考障碍作额外约束，所以不能用于宣称独立建图精度提高。报告把两类结果分开，没有用参考空闲格覆盖自建障碍。

**风险代价的40和0.12有理论保证吗？**
它们是工程权重和长度尺度，鼓励避开敏感边界，不是机器人参数或统计最优估计。有限权重不保证整条路都在共同安全核心；用事后扰动审计报告实际效果。边代价不低于几何距离，所以标准octile仍可作为下界。

**启发函数乘2和风险加权有什么区别？**
乘2改变搜索优先级而不改变目标，可能失去最优性；风险代价改变边权与优化目标，启发函数仍用原几何下界。后者的A*/Dijkstra比较应比较复合代价，不是只比较欧氏路长。

**为什么分层插值可以跨2.5m？会不会造出路？**
这是大平面假设，需要同高度层、最近观测距离≤0.8m、凸包内且无层间冲突，只补未知不覆盖已有表面。确实包含模型推断，所以输出插值掩码并做支持距离敏感性分析；第5组依赖该假设，报告未掩盖。

**状态机为什么不用行为树？**
本题状态少，优先级和迟滞易于验证。任务层级扩展时可用行为树复用动作，但仍需确定性安全约束。LLM可以做高层建议，当前没把它接入实时控制。

**隐藏数据能直接运行吗？**
通用GridMap/search可复用，固定题目驱动和哈希验证器不是任意数据接口。新地图应正确读取配置并验证端点，再调用搜索；不能擅自改原题数据来展示“通过”。

## 现场可练习的代码修改

- 手写 octile 启发式并解释为什么八邻域曼哈顿可能高估。
- 用一个对角障碍小网格说明不允许穿角；定位 search 中对应条件。
- 给定世界点，手算 floor、图像行号翻转及原点偏移，检查是否越界。
- 修改状态机迟滞阈值，并解释为什么进入/退出阈值不同。
- 将风险权重设为0做单独实验输出，比较路径长度和扰动覆盖；不要覆盖提交快照。
- 解释为何官方检查器退出码0不足以代表通过。
